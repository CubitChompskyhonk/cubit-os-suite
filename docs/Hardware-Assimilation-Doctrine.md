# Hardware Assimilation Doctrine v1

## Doctrine
**Grok/Cubit may request. User-owned hardware and user-supplied media only. Session and signal — not silent silicon takeover.**

Phone Assimilate opens OS doors the user allows.  
Hardware Assimilate opens **experience doors** the user allows on a **play session** (emulator host or capture path).

## Layers
| Layer | Meaning | Near-term |
|-------|---------|-----------|
| **A. Emulator / software host** | Game runs under Cubit; framebuffer is fully controllable | **Primary** |
| **B. Capture + overlay** | Real console image + Cubit composite | Secondary |
| **C. Homebrew / flash cart** | Code on user cart | Labs only |
| **D. Internal hardware mod** | Board in signal path | **Deferred** |

## Legal bounds
- No ROM distribution inside Cubit products  
- User loads software they have the right to use  
- No piracy assist, no warehouse of commercial dumps  
- No tools whose primary purpose is permanent console damage  

## Product shape
**Cubit Experience Layer** — toggles first, then **Run experience**:
- Overlay HUD  
- CRT / color grade  
- Guide layer  
- Input map / assist (optional, user-enabled)  

Same mental model as Assimilate permission console.

## Suite placement
OS → **Labs / Play** → Experience Layer  
Assimilate remains phone intake. Games may supply atmosphere packs. HQ holds doctrine + packs metadata.

## Explicitly deferred
Internal N64 (or other) solder/FPGA mods until a separate Founder project.
